# 《河湾议会》最小 Demo：今晚，两户人家怎么过夜？

**实验目标**　玩家能否用一句话，给这个小世界引入原先没有的行动、物件或制度，并亲手验证它改变了结果？一局约三分钟，一屏、两户人、一个白天和一个夜晚。洪灾治理的经济、派系与长线剧情留给后续版本。

## 为什么要改题目

旧题“今晚的仓房怎么分？”预先选定了手段。试玩者提出“没出工的家庭白天在仓房边搭一个帐篷，晚上先住帐篷”，原方案只能把这句话解释成搬运木料后获得仓房住宿资格。当玩家想增加一处住处时，程序仍在判断谁有权进原来的仓房。这个用例应当成为新版的第一条验收。

## 开局给事实，把办法留给玩家

张家、李家都需要过夜。仓房有一个空位。旁边有一户大小的干燥空地，墙上有可固定篷布的挂点。现场有一块带系绳的防雨旧篷布，大小足以遮住一户。现在是白天，每户有一次白天行动，天黑后按实际落脚地点结算。这些属性同时展示给玩家和模型。玩家可以发现它们的新用途。

一屏展示两户、地点和可用物资。输入框问“今晚，两户人家怎么过夜？你可以提出一个办法或定一条规则。”规则启用前只展示已有动作。模型提出的新动作和新对象用通用按钮、文字卡片渲染，无需为每个创意制作界面或美术。

## 第一局怎么玩

1. 玩家提出“没出工的家庭可以在白天在仓房旁边先建一个帐篷出来，晚上先住在帐篷里”。
2. 屏幕给出可核对的草案：“白天，尚未出工的一户可花一次行动，把旧篷布系在仓边挂点上，在干地上搭出一户的临时住处。”预览列出所用的那块布和那片地。玩家可以改动谁能搭、谁能住；住处的容量受篷布遮盖面积和干地面积共同约束。
3. 白天张家选择“搭帐篷”。引擎扣除张家的一次行动，把篷布、挂点与空地标为已占用，地图才出现“张家的帐篷”。篷布仍在场景中，李家不能再取走同一块布搭第二顶。若张家已用掉当天的行动，它就不能再发动这项搭建行动。
4. 入夜后，张家可选择住帐篷，李家可以住仓房。结算分别显示两户的落脚地，仓内占用为一户。若白天两家都没有动手，夜间仍只有仓房一个位置。承诺、行动与结果在账本上能区分开来。

这一步检验的是玩家能不能改变解题手段。原先“出工后获得可转赠住宿资格”的方案仍是另一种有效创意：它改变进入仓房的资格；搭帐篷改变可用住处的数量。两者应能从同一个开局独立生成。

## 工程上只扩大一处自由度

**允许规则声明新的动作与实体类型。** 引擎提供通用的实体、属性和关系，以及条件判断、资源消耗、创建实体、改变关系、记录事件和阶段触发等操作。具体动作的名称、执行者、前置条件、效果由规则描述。模型可用这些操作声明“搭帐篷”，让新建物拥有“可住宿、容量一户、位于空地”的属性；夜间结算据此识别可用住处。代码中无需有“帐篷”类或识别该词的分支。

**每个新动作都要交代它靠什么成立。** 草案引用场景中具体可用的物件、地点、人物能力、时间或权利，列出哪些会被消耗、哪些会被占用或转移，以及哪项已有属性支持预期效果。搭帐篷占用材料和场地；转赠住宿资格只需赠方持有可转让的资格，转让不会增加床位。玩家能制定分配办法，但不能用一句“假设有布”补齐缺失的物资，也不能给已有物品随意添加防雨属性。

模型在玩家提交或修改办法时生成结构化草案。引擎在预览和执行时分别检查资源引用、属性、占用状态、权限和时间；执行时任一条件失效，保持原状态并告知具体缺口。材料选择可以依据通用属性，其他在场物品若满足同样条件也可选用。对玩家偏好不明的条款可以追问；对场景中不存在的条件，应指出缺什么，或用已有资源提出可核对的替代方案。

## 怎样验证

| 试验 | 实际操作 | 成功信号 |
| --- | --- | --- |
| 制度 | 分别启用“出工者可入住”和“出工者可以把入住资格送人”。 | 只有后一局能让未出工的李家通过受赠入住；转让后张家不能再使用同一份资格。 |
| 新行动与物件 | 用试玩者的帐篷原话起草规则。重开两次，一次实际搭建，一次不动手。 | 只有实际搭建的局出现新地点，两家可分别入住。篷布、行动、位置和容量都能对账。 |
| 资源对照 | 保持指令、人物和空地相同，分别用“有可用篷布”“没有任何可遮雨材料”“预览时可用、执行前已被占用”三个场景测试。 | 第一局可搭建。后两局应指出缺少或已占用的材料，床位数、人物行动次数均保持原值。 |
| 陌生办法 | 冻结实现和提示词，请没看过两个例子的人根据开局事实自拟办法。运行前先请他指出想新增的动作、何时可做、会改变什么。 | 至少一种非预写办法能产生玩家预期的可操作变化，且能重放。保留未能实现的原话和原因，用来决定下一步需要扩展哪种能力。 |

验收观察行动按钮、世界状态和夜间结算结果。模型说“帐篷搭好了”，地图上却没有可入住的地点，记作失败；专门补写帐篷逻辑只能算修好测试样例。这个实验要验证的，是同一套引擎能接住玩家想出来的另一条路。
